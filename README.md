# 电商数据仓库 + ETL 项目

## 项目简介

基于玩具电商业务场景，从零搭建一个完整的数据仓库（Data Warehouse），实现从原始订单数据到运营报表的全链路 ETL 流水线。

**技术栈：** Python + pandas + SQLite + SQL

**分层架构：** ODS → DWD → DWS → ADS 四层

---

## 架构设计

```
┌─────────────────────────────────────────────────┐
│                   ADS 应用层                     │
│   运营日报 / 品类排行 / 渠道汇总报表               │
├─────────────────────────────────────────────────┤
│                   DWS 汇总层                      │
│   日×品类汇总 / 渠道汇总 / 地区汇总                │
├─────────────────────────────────────────────────┤
│                   DWD 明细层                      │
│   清洗后的订单明细 + 衍生字段（毛利/毛利率）       │
├─────────────────────────────────────────────────┤
│                   ODS 原始层                      │
│   原始CSV数据原样导入，不做任何修改                │
├─────────────────────────────────────────────────┤
│              数据源：订单CSV（1500条）              │
└─────────────────────────────────────────────────┘
```

---

## 分层说明

| 层级 | 名称 | 作用 | 本项目表 |
|------|------|------|----------|
| ODS | 原始数据层 | 原样存储业务系统导出的数据，保留原始字段 | `ods_orders` |
| DWD | 明细数据层 | 清洗、去重、计算衍生指标，一行一个有效订单 | `dwd_orders_detail` |
| DWS | 汇总数据层 | 按维度聚合（日×品类、渠道、地区），为报表服务 | `dws_daily_category` / `dws_channel_summary` / `dws_region_summary` |
| ADS | 应用数据层 | 直接面向业务报表的结果表 | `ads_daily_report` / `ads_category_rank` |

---

## ETL 流水线

```
data/raw/orders.csv
        │
        ▼  extract.py（抽取）
   ODS 层：ods_orders（1500条原始数据）
        │
        ▼  transform.py（清洗）
   DWD 层：dwd_orders_detail（清洗后 + 毛利/毛利率计算）
        │
        ▼  load.py（汇总）
   DWS 层：按日×品类、渠道、地区聚合
        │
        ▼
   ADS 层：运营日报 + 品类排行报表
```

- Python 3.8+

```bash

# 数据库文件：db/ecommerce_dw.db

```

## 设计思路

1. **为什么分层？** 原始数据和分析数据混在一起，清洗规则一改就要重新处理全部数据。分层后ODS不动，DWD/DWS/ADS各管各的，改一层不影响其他层。

2. **DWD做了什么清洗？**
   - 计算毛利 = 营收 - 成本
   - 计算毛利率 = 毛利 / 营收
   - 标记有效订单（排除"已取消"状态）
   - 统一字段命名

3. **DWS为什么要预聚合？** ADS报表要按天出数，如果每次都从1500条明细跑GROUP BY，数据量大了会慢。DWS提前按日×品类聚合好，ADS直接取数。

4. **为什么用SQLite？** 零安装、一个文件就是数据库，适合演示和作品集展示。生产环境可平滑替换为MySQL/PostgreSQL，SQL语法基本兼容。
